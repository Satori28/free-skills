# Motion-видео

Работай с **исходной сценой и шкалой времени**, если они доступны. Готовый MP4 — результат экспорта, а не основной файл для правки. Сохраняй предыдущую версию ролика, чтобы пользователь мог сравнить варианты.

## Найди рабочий проект

1. Прочти `AGENTS.md`, `README.md`, сценарий и заметки по сценам в репозитории. Найди исходники, ассеты, звук, команду сборки и последний экспорт. Не считай название MP4 доказательством того, что это актуальная версия.
2. Определи стек по файлам проекта. Для HyperFrames посмотри шкалу через `npx hyperframes timeline --json`; для другого стека используй его сцену, редактор или конфигурацию. Установи, где лежат текст, переходы, персонаж, логотип, музыка и SFX.
3. Если сведений нет, оставь в проекте короткую карту: сюжет и таймкоды, стек, редактируемые файлы, источники медиа, команда экспорта. Указывай реальные пути проекта, не пути своего компьютера.

| Задача | Обычно подходит | Где искать правку |
| --- | --- | --- |
| Кинетический текст, UI, курсор, карточки, переходы | HyperFrames (HTML/CSS/GSAP) или Motion Canvas (TypeScript) | Композиция, сцены, таймлайн, стили |
| Рисованная графика, кадры, вычисляемые кодом | Canvas JS / p5.js | JS/HTML и функция кадра |
| Схемы и математическая графика | Manim | Python-сцены |
| Объёмный объект или персонаж | Blender | `.blend`, материалы, камера, скрипт сборки |
| Повторяемый ролик на React-компонентах | Remotion, если он уже выбран в проекте | React-композиция и props |

Для интерфейсного ролика начинай с HyperFrames или Motion Canvas. Blender подключай к конкретному 3D-эпизоду, а затем компонуй его с остальными сценами. Следуй выбранному пользователем стеку; не переносись на другой только ради локальной правки. Если доступны skills `hyperframes`, `hyperframes-core`, `hyperframes-animation` и `media-use`, используй их для соответствующих задач; `javascript-animation` — для Canvas, `soundtrack` — для музыки и синхронизации. Они дополняют исходники проекта, а не заменяют их.

## Новый ролик

Сначала задай короткий сюжет целиком: последовательность сцен, главный жест в каждой, длительности, переходы и звуковые акценты. Затем собери первые 2–3 сцены, проверь их стык и только после этого расширяй ролик. Динамику создают смена масштаба и плана, направленные входы, паузы для чтения и акценты на остановках; одни только карточки не заменяют режиссуру.

## Правка готового варианта

Открой [QUICK-EDITS.md](QUICK-EDITS.md), когда пользователь прислал скриншот или просит изменить элемент, скорость либо звук. Скриншот помогает найти **сцену и объект**: меняй его в исходнике на нужном отрезке, а не закрашивай один кадр MP4. Если время не указано, сопоставь скриншот с текстом и сценой; спрашивай таймкод только при реальной неоднозначности.

- **Положение, текст, цвет, логотип:** найди элемент и его контейнер, исправь композицию и проверь соседние элементы на наложение. Для бренда используй предоставленный SVG или другой исходный ассет.
- **Слишком быстро или резко:** меняй длительности сцен, паузы, easing и переходы; синхронно передвигай звуковые события. Не замедляй весь готовый MP4, если доступна редактируемая шкала.
- **Музыка:** замени фоновую дорожку отдельно от SFX, подгони длительность и плавный вход/выход. Источником может быть локальный файл или доступный каталог, например HeyGen; не предполагай, что внешний сервис подключён. SFX привязывай к действиям: whoosh для входа, impact для остановки, click для UI, sweep для перехода. Музыка поддерживает ритм и не забивает действия.
- **Персонаж:** меняй 3D-исходник только для внешности, света и движения 3D-объекта. Положение окна, текст и момент появления обычно правятся в композиции.

После правки выполни проверку проекта (`npm run check` для настроенного HyperFrames-проекта), экспортируй новый файл и технически проверь длительность, размер, частоту кадров, видеокодек и звук через `ffprobe`; при необходимости проверь полное декодирование через FFmpeg. Если визуальный или слуховой просмотр не проводился либо пользователь его запретил, так и скажи. Не объявляй субъективное качество проверенным по одному успешному рендеру.

При передаче первой рабочей версии дай пользователю **короткий список того, что теперь можно поменять**, с готовыми фразами: элемент по скриншоту, текст, скорость, переход, музыка, звук, логотип. Не требуй профессиональных терминов или покадрового ТЗ.
