# Порядок работы с Free Skills

Для разработки каждая роль читает свой `.codex/agents/<role>.toml`, `skills/development/<role>/SKILL.md` и указанные там вспомогательные файлы. Передавайте постановку и результат через документы и PR в GitHub, чтобы следующая роль видела полный контекст. Для нового motion-ролика или правки готового варианта прочти `skills/motion-video/SKILL.md`; короткие примеры запросов — в `skills/motion-video/QUICK-EDITS.md`.

## Среда

- Установите ChatGPT Desktop и войдите в свой аккаунт. Удобная раскладка: слева локальные задачи разработчика и ревьюера, справа встроенный браузер с продуктовым менеджером, техлидом и финальным аудитором.
- Для браузерных ролей войдите в свой GitHub во встроенном браузере и подключите GitHub через раздел Plugins. Агент может помочь найти и установить плагин; вход и предоставление доступа выполняет владелец аккаунта.
- Для локальных ролей откройте проект на компьютере и настройте Git с доступом к GitHub, например через `gh auth login`. Все роли работают с одним целевым репозиторием и связанными PR.

## Цепочка

1. **Product Manager — браузер.** Для крупной или новой продуктовой задачи определяет поведение продукта, записывает его в `docs/product.md` и открывает draft PR. Если задача небольшая и продуктовая логика уже описана, начните с техлида.
2. **Tech Lead — браузер.** По продуктовой постановке и коду готовит техническое задание. Выбирает один PR или несколько последовательных PR; крупную задачу делит по проверяемым границам, без искусственного дробления. Продолжает draft PR или оформляет PR текущего этапа в GitHub и передаёт задачу разработчику.
3. **Developer — локально.** По утверждённому ТЗ реализует текущий PR и проверяет результат.
4. **Code Reviewer — локально.** Проверяет код и полный сценарий, исправляет связанные с задачей дефекты, добавляет нужные тесты.
5. **Logic Auditor — браузер.** После ревью выполняет финальный аудит PR. Если нашёл обязательные исправления, возвращает PR разработчику и ревьюеру; после исправлений проверяет снова.

На каждом шаге следуйте границам соответствующего Skill. ТЗ и код фиксируйте в целевом репозитории; результаты проверок оформляйте по правилам ревьюера и аудитора.
